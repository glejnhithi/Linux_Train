# Processes

## crontab
Komanda crontab i jep përdoruesit mundësinë të planifikojë detyra që të ekzekutohen në një kohë specifike ose me një interval specifik. Nëse dëshironi të kaloni përtej përdorimit të Linux nga një ndërfaqe grafike përdoruesi, ka shumë mundësi që të dëshironi të planifikoni një detyrë të ekzekutohet në një kohë ose interval të caktuar. Edhe vetëm mësimi rreth saj mund t’ju japë ide se çfarë mund të bëni.

    • crontab [-u user] [-l | -r | -e] : Planifiko një detyrë të ekzekutohet në një kohë ose interval të caktuar

Për shembull, mund të planifikoni një script të ekzekutohet çdo ditë për të kryer një proces backup në mes të natës, ose të kapë disa të dhëna çdo orë për t’i ruajtur në një databazë.

## Komanda crontab
Komanda crontab është një bashkim i “cron table” sepse përdor planifikuesin e detyrave cron për të ekzekutuar detyra që ruhen në një lloj “tabele” në skedarin crontab të përdoruesit. cron është emëruar sipas “Khronos”, personifikimi grek i kohës.

Ndërsa çdo përdorues që krijon një detyrë përmes crontab krijon një skedar crontab, ky skedar nuk është menduar të editohet manualisht. Ai ndodhet në vende të ndryshme në variante të ndryshme të shpërndarjeve Linux dhe mënyra më e besueshme për ta edituar është duke ekzekutuar komandën crontab -e. Çdo përdorues ka skedarin e vet crontab dhe përdoruesi root mund të editojë skedarin crontab të një përdoruesi tjetër. Kjo është situata ku do të përdornim opsionin -u, por sinqerisht kur të arrijmë në atë fazë mund të supozohet se dimë mjaftueshëm rreth Linux.

Ekzistojnë vetëm tre opsione kryesore që përdoren me crontab.

## Opsionet
Opsioni i parë që duhet të shohim është opsioni -l që na lejon të listojmë skedarin crontab;

    crontab -l

Pasi të ekzekutohet do të listojë përmbajtjen e skedarit crontab direkt në ekran. Output-i do të duket diçka si më poshtë;

    # Edit this file to introduce tasks to be run by cron.
    #
    # Each task to run has to be defined through a single line
    # indicating with different fields when the task will be run
    # and what command to run for the task
    #
    # To define the time you can provide concrete values for
    # minute (m), hour (h), day of month (dom), month (mon),
    # and day of week (dow) or use '*' in these fields (for 'any').#
    # Notice that tasks will be started based on the cron's system
    # daemon's notion of time and timezones.
    #
    # Output of the crontab jobs (including errors) is sent through
    # email to the user the crontab file belongs to (unless redirected).
    #
    # For example, you can run a backup of all your user accounts
    # at 5 a.m every week with:
    # 0 5 * * 1 tar -zcf /var/backups/home.tgz /home/
    #
    # For more information see the manual pages of crontab(5) and cron(8)
    #
    # m h dom mon dow command
    */10 * * * * /usr/bin/php /home/pi/scrape-books.php

Këtu mund të shohim që pjesa kryesore e skedarit (në fakt gjithçka përveç rreshtit të fundit) janë komente që shpjegojnë si të shtohet një hyrje në skedarin crontab.

Hyrja në këtë rast është specifikuar të ekzekutohet çdo 10 minuta dhe kur të ekzekutohet, do të nisë script-in PHP scrape-books.php (do të shpjegojmë më vonë si kodifikohet kjo në seksionin e shembujve).

Nëse duam të heqim crontab aktual mund të përdorim opsionin -r. Ndoshta jo diçka që do ta bënim rregullisht, sepse zakonisht do të ishte më e zakonshme të editonim përmbajtjen sesa ta fshijmë plotësisht.

Së fundi ekziston opsioni për të edituar skedarin crontab që iniciohet duke përdorur -e. Ky është opsioni kryesor që do të përdoret dhe ai që do të mbulojmë më në detaje në shembujt më poshtë.

## Shembuj
Si shembull, konsideroni që duam të ekzekutojmë një script Python çdo ditë në orën 6 të mëngjesit. Komanda e mëposhtme do të na lejojë të editojmë crontab;

    crontab -e

Pasi të ekzekutohet do të hapë crontab në editorin default të sistemit tuaj (me shumë mundësi ‘vi’, ‘vim’ ose ‘nano’). Skedari do të duket si më poshtë;
 
    # Edit this file to introduce tasks to be run by cron.
    #
    # Each task to run has to be defined through a single line
    # indicating with different fields when the task will be run
    # and what command to run for the task
    #
    # To define the time you can provide concrete values for
    # minute (m), hour (h), day of month (dom), month (mon),
    # and day of week (dow) or use '*' in these fields (for 'any').#
    # Notice that tasks will be started based on the cron's system
    # daemon's notion of time and timezones.
    #
    # Output of the crontab jobs (including errors) is sent through
    # email to the user the crontab file belongs to (unless redirected).
    #
    # For example, you can run a backup of all your user accounts
    # at 5 a.m every week with:
    # 0 5 * * 1 tar -zcf /var/backups/home.tgz /home/
    #
    # For more information see the manual pages of crontab(5) and cron(8)
    #
    # m h dom mon dow command

Siç u përmend më herët, skedari default përfshin disa shpjegime mbi mënyrën si formatohet një hyrje në crontab. Në rastin tonë duam të shtojmë një hyrje që i thotë script-it të nisë në 6 orë dhe 0 minuta çdo ditë. crontab pranon gjashtë pjesë informacioni që lejojnë këtë veprim të kryhet. Secila prej këtyre pjesëve ndahet me një hapësirë.

    1.Një numër (ose interval numrash), m, që përfaqëson minutën e orës (vlerat valide 0-59);
    2.Një numër (ose interval numrash), h, që përfaqëson orën e ditës (vlerat valide 0-23);
    3.Një numër (ose interval numrash), dom, që përfaqëson ditën e muajit (vlerat valide 0-31);
    4.Një numër (ose listë, ose interval), ose emër (ose listë emrash), mon, që përfaqëson muajin e vitit (vlerat valide 1-12 ose Jan-Dec);
    5.Një numër (ose listë, ose interval), ose emër (ose listë emrash), dow, që përfaqëson ditën e javës (vlerat valide 0-6 ose Sun-Sat); dhe
    6.command, që është komanda që do të ekzekutohet, saktësisht siç do të shfaqej në command line.

## Struktura është si më poshtë;

    Linux permissions as rwx

Duke supozuar që duam të ekzekutojmë një script Python të quajtur ‘m_temp.py‘ që ndodhet në home directory të ‘pi’, rreshti që do të donim të shtonim do të ishte si më poshtë;

    0 6 * * * /usr/bin/python /home/pi/m_temp.py

Pra në minutën 0, orën 6, çdo ditë të muajit (ku asterisku nënkupton ‘gjithçka’), çdo muaj, çdo ditë të javës ekzekutojmë komandën /usr/bin/python /home/pi/m_temp.py (që, nëse do të ishim në command line në home directory të pi do ta ekzekutonim si python m_temp.py, por meqë nuk mund të garantojmë ku do të jemi kur script-i të ekzekutohet, po japim path-in e plotë për komandën python dhe script-in m_temp.py.

Nëse duam ta ekzekutojmë komandën dy herë në ditë (6am dhe 6pm (1800hrs)) mund të japim një vlerë të ndarë me presje në fushën e orëve (h) si më poshtë;

    0 6,18 * * * /usr/bin/python /home/pi/m_temp.py

Nëse duam ta ekzekutojmë komandën në 6am por vetëm gjatë ditëve të javës (e hënë deri të premte) mund të japim një interval në fushën dow si më poshtë (duke kujtuar që 0 = e diel);

    0 6 * * 1-5 /usr/bin/python /home/pi/m_temp.py

Nëse duam të ekzekutojmë të njëjtën komandë çdo 2 orë mund të përdorim notacionin */2, kështu që rreshti ynë në crontab do të dukej si më poshtë;

    0 */2 * * * /usr/bin/python /home/pi/m_temp.py

Është e rëndësishme të theksohet që duhet të përfshijmë 0 në fillim (në vend të *) në mënyrë që të mos ekzekutohet çdo minutë çdo 2 orë (pra çdo minutë në përgjithësi).

# kill
Komanda kill na lejon të përfundojmë një proces duke i dërguar një sinjal. Ajo mund të dërgojë sinjale të ndryshme në varësi të sa e vështirë është ndalimi i procesit. Ajo mbështetet në njohjen e numrit të Identifikimit të Procesit (PID) të procesit. Komanda kill është një mjet i rëndësishëm administrativ për të siguruar që sistemi po funksionon siç duhet.

    • kill [options] PID(s) : dërgon një sinjal për të përfunduar një proces ose procese sipas PID

Duke supozuar që kemi përcaktuar tashmë se PID që dëshirojmë të përfundojmë është 798, gjithçka që duhet të bëjmë është të ekzekutojmë komandën e mëposhtme;

    kill 798

Nuk ka feedback në command line për të treguar suksesin ose dështimin, por kjo mund të realizohet duke përdorur një komandë tjetër si ps.

## Komanda ‘kill’
Qëllimi i deklaruar i komandës kill është direkt në emër. Objekti është të “vrasë” një proces për ta ndaluar së ekzekutuari. Kjo mund të jetë sepse duhet të mbyllet në mënyrë të rregullt si funksion natyral i asaj që po kryen kompjuteri, ose mund të kërkohet për të ndaluar një program që është bërë jo-përgjigjës (unresponsive). Në këtë aspekt është shumë e ngjashme me komandën killall e cila do të përfundojë një proces bazuar në komandën origjinale që e ka nisur atë.

Një nga keqkuptimet më të mëdha me komandat kill dhe killall është se roli i tyre nuk është thjesht të “shkëpusin prizën” e një procesi. Puna e tyre është të dërgojnë një sinjal te një proces duke i kërkuar të mbyllet. Ndonjëherë një proces është rezistent ndaj këtij instruksioni dhe duhet të dërgohet një sinjal më serioz. Komanda kill mund ta bëjë edhe këtë.

Një nga aspektet më të rëndësishme të përdorimit të komandës kill është se duhet të përcaktojmë numrin e Identifikimit të Procesit (PID) të procesit që do të përfundohet para se të ekzekutojmë komandën kill. Për ta bërë këtë, dy opsione të mira janë komandat ps dhe/ose top. Secila prej tyre mund të përdoret me opsionet e veta për të përcaktuar PID-in e duhur dhe pasi ta kemi atë mund të përdorim kill.

Siç u përmend, funksioni i komandës kill është të dërgojë një sinjal te një proces. Gama e sinjaleve të mundshme që mund të dërgohen mund të gjendet duke ekzekutuar komandën kill me opsionin -l (për qartësi, kjo është shkronja e vogël L, jo numri 1). Prandaj mund ta ekzekutojmë komandën si më poshtë;
    
    kill -l
... që do të rezultojë në listën e mëposhtme të sinjaleve të mundshme;

Në mënyrë default (pa specifikuar një sinjal) komanda kill do të përdorë sinjalin 15 ‘SIGTERM’. Nëse një proces reziston ndaj kësaj përpjekjeje për ta mbyllur, është praktikë e zakonshme të përdoret sinjali 9 që është ‘SIGKILL’. Kjo do të realizohej si më poshtë (duke supozuar se kemi përcaktuar tashmë që PID që duam të përfundojmë është 798);

    kill -9 798

Është një situatë e pazakontë të gjendet një proces që nuk mund të përfundohet me komandën kill -9. E vetmja herë kur kjo nuk duhet të jetë efektive është nëse procesi po bën një kërkesë ndaj bërthamës së sistemit operativ (kernel). Edhe atëherë, kur të përfundojë kërkesa, ai duhet të mbyllet.

Nëse duam të përfundojmë më shumë se një proces mund t’i ndajmë thjesht me hapësirë si më poshtë;

    kill 798 1234 666 999

# killall

Komanda killall na lejon të përfundojmë një proces ose procese duke i dërguar një sinjal. Ajo mund të dërgojë sinjale të ndryshme në varësi të asaj se sa e vështirë është ndalimi i procesit. Është shumë e ngjashme me komandën kill në funksion, por nuk mbështetet në njohjen e numrit të identifikimit të procesit (PID). Në vend të kësaj, ajo mund të përdorë emrin e komandës që ka nisur procesin dhe si rezultat, kur ekzekutohet, mund të përfundojë të gjitha proceset e nisura me atë komandë. Komanda killall është një mjet i rëndësishëm administrativ për të siguruar që sistemi po funksionon siç duhet.

    • killall [options] command name : dërgon një sinjal për të përfunduar një proces ose procese sipas emrit

Duke supozuar që kemi tashmë një proces me emrin top duke u ekzekutuar, gjithçka që duhet të bëjmë është të ekzekutojmë komandën e mëposhtme;

    killall top

Nuk ka feedback në command line për të treguar suksesin ose dështimin, por kjo mund të realizohet duke përdorur një komandë tjetër si ps.

## Komanda killall

Qëllimi i deklaruar i komandës killall është pikërisht në emër. Objekti është të vrasë të gjitha proceset me një emër specifik për t’i ndaluar ato së ekzekutuari. Kjo mund të ndodhë sepse ato duhet të mbyllen në mënyrë të rregullt si pjesë normale e funksionimit të kompjuterit, ose mund të kërkohet për të ndaluar programe që janë bërë jo-responsive.

Një nga keqkuptimet më të mëdha me komandat kill dhe killall është se roli i tyre nuk është thjesht të shkëpusin energjinë e një procesi. Detyra e tyre është t’i dërgojnë një sinjal një procesi ose proceseve duke u kërkuar të mbyllen. Ndonjëherë një proces i reziston këtij instruksioni dhe duhet të dërgohet një sinjal më serioz. Komanda killall mund ta bëjë edhe këtë.

Mund të duket e qartë, por një nga aspektet më të rëndësishme të përdorimit të komandës killall është se duhet të përcaktojmë emrin e procesit që do të përfundohet para se të ekzekutojmë komandën. Për ta bërë këtë, disa opsione të mira janë komandat ps dhe/ose top. Secila prej tyre mund të përdoret me opsionet përkatëse për të përcaktuar emrin e duhur dhe më pas mund të përdorim killall.

Siç u përmend, funksioni i komandës killall është të dërgojë një sinjal te një proces. Gama e sinjaleve të mundshme që mund të dërgohen mund të shihet duke ekzekutuar komandën killall me opsionin -l (për qartësi, është shkronjë e vogël L, jo numri 1). Mund ta ekzekutojmë komandën si më poshtë;

    killall -l

... që do të rezultojë në listën e mëposhtme të sinjaleve të mundshme;

    HUP INT QUIT ILL TRAP ABRT IOT BUS FPE KILL USR1 SEGV USR2 PIPE ALRM TERM
    STKFLT CHLD CONT STOP TSTP TTIN TTOU URG XCPU XFSZ VTALRM PROF WINCH IO PWR SYS
    UNUSED

Si parazgjedhje (pa specifikuar një sinjal) komanda kill do të përdorë sinjalin SIGTERM. Duhet të vërejmë në këtë pikë se ky sinjal nuk shfaqet në listën e sinjaleve të listuara nga komanda killall -l. Kjo ndodh sepse sinjalet e listuara aty nuk kanë shkronjat SIG përpara tyre. Pra, nëse duam të dërgojmë një sinjal SIGKILL, duhet të ekzekutojmë komandën me opsionin -s dhe emrin e plotë të sinjalit si më poshtë (duke supozuar se kemi përcaktuar tashmë që procesi top është ai që duam të përfundojmë);

    killall -s SIGKILL top

Është një situatë e pazakontë të gjesh procese që nuk mund të përfundohen me komandën killall -s SIGKILL. E vetmja herë kur kjo nuk duhet të funksionojë është nëse proceset po bëjnë një kërkesë ndaj bërthamës së sistemit operativ (kernel). Edhe atëherë, pasi ta kenë përfunduar kërkesën, ato duhet të mbyllen.

Nëse duam të përfundojmë më shumë se një proces me emër, mund t’i ndajmë thjesht me hapësirë si më poshtë;

    killall top nano

Kjo duhet të përfundojë proceset top dhe nano.

# ps

Komanda ps shfaq një “snapshot” të proceseve që po ekzekutohen. Ngjashëm me komandën top, komanda ps do të raportojë proceset së bashku me karakteristikat përkatëse dhe ekzistojnë shumë mënyra të ndryshme për t’i paraqitur ato. Megjithatë, ndërsa top përditësohet vazhdimisht, ps ofron një raport statik. Kjo është një komandë tjetër e dobishme për troubleshooting dhe për të kuptuar funksionimin e sistemit.

    • ps [options] : shfaq një snapshot të proceseve aktuale

Për të parë një listë të proceseve në ekzekutim mund të ekzekutojmë komandën e mëposhtme;
    
    ps -aux | less
Në fakt janë dy komanda ku output-i i ps dërgohet (pipe) te komanda less në mënyrë që lista e gjatë të mund të shqyrtohet një faqe njëherësh. Faqja e parë e output-it do të duket pak a shumë si kjo;

    root 2 0.0 0.0 0 0 ? S 06:08 0:00 [kthreadd]
    root 3 0.0 0.0 0 0 ? S 06:08 0:01 [ksoftirqd/0]
    root 5 0.0 0.0 0 0 ? S< 06:08 0:00 [kworker/0:0H]
    root 6 0.0 0.0 0 0 ? S 06:08 0:03 [kworker/u8:0]

Output-i tregon një ndjesi të ngjashme me komandën top, në kuptimin që shohim një listë procesesh dhe disa informacione rreth tyre, por informacioni i paraqitur këtu është pak më ndryshe. Opsionet e përdorura me komandën i tregojnë asaj të listojë proceset e të gjithë përdoruesve (-a), të japë disa detaje rreth proceseve (u) dhe të përfshijë proceset që nuk kanë terminal kontrollues (x). Kjo është një komandë shumë e zakonshme për administrimin e një sistemi Linux.

## Komanda ps

Komanda ps synon të raportojë statusin e proceseve që po ekzekutohen aktualisht.

Nëse ekzekutohet pa opsione, ajo kthen vetëm katër pjesë informacioni për të paktën dy proceset që do të jenë duke u ekzekutuar: shell-i dhe vetë komanda ps.

    ps
    output 
    PID TTY TIME CMD
    788 pts/0 00:00:01 bash
    1642 pts/0 00:00:00 ps
Këtu mund të shohim sa vijon;

    • Process ID i procesit (788)
    • Terminal TYpe ose emri i terminalit ku përdoruesi është loguar (pts/0)
    • Koha totale e CPU-së që procesi ka përdorur që nga nisja (00:00.01)
    • CoMmanD që është përdorur për të nisur procesin (bash)

Natyrisht, kjo sasi informacioni është disi e kufizuar, prandaj komanda ps zakonisht përdoret me një kombinim opsionesh.

## Options

Ndërsa ka disa opsione të disponueshme, ato më së shpeshti përdoren në kombinim dhe pipe-ohen te less ose grep për të kontrolluar informacionin e kthyer. Opsionet më të përdorura janë;

    • -a : liston proceset e të gjithë përdoruesve
    • -u : shfaq rezultatet në një format të orientuar nga përdoruesi
    • -x : përfshin proceset pa terminale kontrolluese
    • -e : përfshin çdo proces që po ekzekutohet aktualisht
    • -f : bën një listim të plotë të detajeve për proceset

Duke rikthyer shembullin fillestar që treguam më herët;

    ps -aux | less
output
    
    USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
    root 1 0.0 0.4 5376 3944 ? Ss 06:08 0:07 /sbin/init
    root 2 0.0 0.0 0 0 ? S 06:08 0:00 [kthreadd]
    root 3 0.0 0.0 0 0 ? S 06:08 0:01 [ksoftirqd/0]
    root 5 0.0 0.0 0 0 ? S< 06:08 0:00 [kworker/0:0H]

Kur bëhet në terminal, opsioni -a siguron që të gjitha proceset të listohen (edhe pse less do të kontrollojë shfaqjen e tyre). Opsioni -x përfshin ato procese që nuk kanë terminale kontrolluese dhe opsioni -u e paraqet informacionin në një format më të detajuar. Kolonat e ndryshme në këtë format më të detajuar përfaqësojnë;

    • USER : përdoruesi nën të cilin po ekzekutohet procesi.
    • %CPU : përqindja e kohës që procesi ka përdorur CPU-në që nga nisja e tij.
    • %MEM : përqindja e memories reale të përdorur nga ky proces.
    • VSZ : madhësia (në kilobyte) e procesit në memorien virtuale.
    • RSS : madhësia e memories reale të procesit (në kilobyte).
    • STAT : statusi i procesit.
    • START : kur është nisur procesi.
    • TIME : koha që procesi ka qenë duke u ekzekutuar.
    • COMMAND : komanda që ka nisur procesin.

Kolona STAT përfshin një grup kodesh për të përshkruar statusin e proceseve. Këto mund të interpretohen me karakteret e mëposhtme;

    • D gjumë i pandërprerë (zakonisht IO)
    • R running ose runnable (në run queue)
    • S gjumë i ndërprershëm (duke pritur për një event të përfundojë)
    • T ndalur, ose nga një sinjal kontrolli pune ose sepse po gjurmohet
    • W paging (jo valid që nga kernel 2.6.xx)
    • X dead (nuk duhet të shihet kurrë)
    • Z proces defunct (“zombie”), i përfunduar por jo i marrë nga parent-i
    • < prioritet i lartë (jo “nice” me përdoruesit e tjerë)
    • N prioritet i ulët (nice me përdoruesit e tjerë)
    • L ka faqe të bllokuara në memorie (për real-time dhe custom IO)
    • s është session leader
    • l është multi-threaded
    • + është në foreground process group

# top

Komanda top përdoret për të shfaqur në kohë reale një përmbledhje të informacionit të sistemit dhe proceseve që po ekzekutohen në kompjuter. top është interaktive dhe mund të kontrollohet dhe konfigurohet gjatë përdorimit për të ndihmuar në identifikimin e aspekteve të ndryshme të funksionimit të sistemit. Kjo është një komandë jashtëzakonisht e dobishme për të monitoruar kërkesat që ndryshojnë në sistem dhe ndryshimet ndërsa proceset kryejnë detyrat e tyre.

• top [options] : shfaq informacionin e sistemit dhe proceseve në kohë reale

Rreshti i parë në krye tregon sa kohë sistemi ka qenë aktiv, sa përdorues janë të lidhur dhe sa është ngarkesa (load) e sistemit. Rreshti i dytë tregon një përmbledhje të proceseve. Poshtë tyre ndodhet një tabelë me proceset, karakteristikat dhe gjendjet e tyre.

Informacioni i shfaqur përditësohet në intervale të rregullta (zakonisht çdo 3 sekonda). Komanda top mund të mbyllet duke shtypur q (quit).

## Komanda top

Komanda top është një nga komandat më të përdorura për monitorimin e performancës së sistemit, kryesisht për shkak të gamës së gjerë të parametrave që mund të shihen dhe opsioneve të disponueshme për konfigurimin e informacionit të shfaqur. Emri “top” vjen sepse është shumë e dobishme për të identifikuar proceset që përdorin më shumë burime në sistem.

Duhet të fillojmë me përshkrimin e parametrave të ndryshëm që shfaqen në pamjen standarde dhe më pas të shohim komandat interaktive të disponueshme.

## Rreshti i parë

Rreshti i parë nga shembulli ynë duket kështu;

    top - 08:50:22 up 2:41, 1 user, load average: 0.00, 0.01, 0.05

Informacioni i paraqitur këtu (me radhë) është;

    • Ora aktuale (08:50:22)
    • Koha që sistemi ka qenë aktiv (2 orë e 41 minuta)
    • Numri i përdoruesve të lidhur (1)
    • Ngarkesa mesatare e sistemit në 1 minutën e fundit (0.00), 5 minutat e fundit (0.01) dhe 15 minutat e fundit (0.05)

## Rreshti i dytë

 Rreshti i dytë duket kështu;

Tasks: 86 total, 1 running, 85 sleeping, 0 stopped, 0 zombie

Informacioni i paraqitur është;

    • Numri total i proceseve (86)
    • Numri i proceseve aktive (1)
    • Numri i proceseve në gjendje pritjeje (85)
    • Numri i proceseve të ndaluara (0)
    • Numri i proceseve zombie (0)

Një proces zombie është një proces që ka përfunduar ekzekutimin, por ende ka një hyrje në tabelën e proceseve. Kjo zakonisht ndodh sepse procesi prind ende duhet të lexojë statusin e daljes së procesit fëmijë.

## Rreshti i tretë

Rreshti i tretë duket kështu;

    %Cpu(s): 0.1 us, 0.2 sy, 0.0 ni, 99.7 id, 0.0 wa, 0.0 hi, 0.1 si, 0.0 st

Informacioni i paraqitur është;
    
    • Përqindja e CPU për proceset e përdoruesit (0.1)
    • Përqindja e CPU për proceset e sistemit (0.2)
    • Përqindja e CPU për procese me prioritet të ndryshuar (nice) (0.0)
    • Përqindja e CPU që nuk përdoret (idle) (99.7)
    • Përqindja e CPU që pret operacione I/O (0.0)
    • Përqindja e CPU që shërben ndërprerje hardware (0.0)
    • Përqindja e CPU që shërben ndërprerje software (0.1)
    • Përqindja e CPU e marrë nga hypervisor për detyra të tjera (0.0)

Rreshtat e katërt dhe të pestë

    KiB Mem: 948108 total, 139600 used, 808508 free, 14908 buffers
    KiB Swap: 102396 total, 0 used, 102396 free. 82084 cached Mem

Rreshti i katërt tregon përdorimin e memories fizike (RAM), ndërsa rreshti i pestë tregon përdorimin e memories swap.

    Mem

Mem i referohet memories fizike të disponueshme në sistem. Kjo është memoria RAM që përdoret gjatë ekzekutimit të aplikacioneve dhe përpunimit të të dhënave.

    Swap

Swap është memorie e rezervuar në disk për të ndihmuar sistemin kur RAM mbushet. Përdorimi i swap mund të tregojë që sistemi ka nevojë për më shumë RAM.

Kini parasysh që kur përdoret swap, vlera “used” mund të mbetet e lartë edhe pasi përdorimi real ka përfunduar.

    Buffers / Cache

Një buffer është një pjesë e memories që përdoret si vend i përkohshëm për të dhënat që dërgohen ose merren nga pajisje të jashtme si HDD, printer, tastierë ose rrjet.

Cache është një zonë memorieje që ruan të dhëna të përdorura shpesh për akses më të shpejtë.

Të dyja janë zona të përkohshme për përpunimin e të dhënave.

Rreshtat tregojnë;

    • Memoria totale
    • Memoria e përdorur
    • Memoria e lirë
    • Memoria e përdorur si buffer (14908)
    • Memoria e përdorur si cache (82084)

## Tabela e proceseve

Tabela e proceseve duket kështu;

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    1231 pi 20 0 5092 2480 2148 R 0.7 0.3 0:00.15 top
    1026 root 20 0 0 0 0 S 0.3 0.0 0:02.66 kworker/0:0
    1 root 20 0 5376 3944 2792 S 0.0 0.4 0:05.79 systemd
    2 root 20 0 0 0 0 S 0.0 0.0 0:00.00 kthreadd

Kjo tabelë tregon;

    • PID — ID e procesit
    • USER — përdoruesi pronar i procesit
    • PR — prioriteti i procesit
    • NI — vlera nice
    • VIRT — memoria virtuale e përdorur
    • RES — memoria fizike e përdorur
    • SHR — memoria e përbashkët
    • S — statusi i procesit (S=sleeping, R=running, Z=zombie)
    • %CPU — përqindja e CPU-së së përdorur
    • %MEM — përqindja e RAM-it të përdorur
    • TIME+ — koha totale e CPU-së që ka përdorur procesi
    • COMMAND — komanda që nisi procesin

## Komandat interaktive

Pasi top është në ekzekutim, përveç q për dalje, komanda më e dobishme është h për të shfaqur ekranin e ndihmës.

    h

Kjo do të tregojë komandat e disponueshme për top.

Një komandë interesante që nuk shfaqet aty është A, e cila hap një ekran tjetër me edhe më shumë informacion.

    A

Kjo do të shfaqë disa tabela shtesë me informacion më të detajuar për proceset dhe sistemin.
